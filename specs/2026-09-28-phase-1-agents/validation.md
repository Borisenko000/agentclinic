# Фаза 1. Агенты — валидация

Ветку `feature/phase-1-agents` можно вливать в `main`, только когда выполнены **все**
пункты ниже. Каждый пункт проверяется фактическим запуском, а не «должно работать».

## 1. Автоматические проверки (GitHub Actions, все jobs зелёные)

| Job | Команды | Что доказывает |
|-----|---------|----------------|
| `backend` | `./mvnw verify` | Миграции V1–V3 применяются; MockMvc-тесты агентов, health и тест снимка OpenAPI проходят. |
| `frontend` | `npm ci` → `npm run api:generate` + `git diff --exit-code` → `lint` → `format:check` → `test` → `build` | Типы клиента соответствуют закоммиченному контракту; Vitest-тесты проходят; сборка успешна **без запущенного бэкенда**. |
| `e2e` | `npx playwright install --with-deps chromium` → `npm run test:e2e` | Smoke фазы 0 и сценарий агентов проходят на настоящих Spring Boot и Next.js. |

Условие: CI запущен на последнем коммите PR, ни один тест не пропущен (`skip`/`only`).

## 2. Обязательное содержимое тестов

### Бэкенд (MockMvc, временная БД)

- **Миграции:** в `flyway_schema_history` есть версии 1, 2, 3 с `success = true`.
- **`GET /api/agents`:** `200`, массив seed-агентов, отсортированный по имени без учёта
  регистра; у элемента есть `id`, `name`, `model`, `vendor`, `description`, `createdAt`
  (ISO-8601).
- **`GET /api/agents/{id}`:**
  - существующий → `200` с полным телом;
  - несуществующий → `404`, `Content-Type: application/problem+json`;
  - нечисловой id → `400` ProblemDetail.
- **`POST /api/agents`:**
  - валидное тело → `201`, `Location: /api/agents/{id}`, тело совпадает с последующим
    `GET` по этому адресу;
  - пустое или однобуквенное `name`, пустое `model`, `vendor` > 60, `description`
    > 1000 → `400` ProblemDetail, `errors` содержит соответствующее поле;
  - имя, совпадающее с существующим без учёта регистра (проверить латиницу **и**
    кириллицу) → `409` ProblemDetail, `errors.name`;
  - пробелы по краям обрезаются; пустые `vendor`/`description` возвращаются как `null`.
- **Снимок OpenAPI:** `/v3/api-docs` совпадает с `openapi/openapi.json`; в снимке
  описаны все три операции и схемы `AgentResponse`, `CreateAgentRequest`.

### Фронтенд (Vitest + React Testing Library)

- **`AgentList`:** имя, модель и вендор каждого агента; ссылки на `/agents/{id}`;
  пустое состояние со ссылкой на регистрацию.
- **`AgentProfile`:** все поля; дата регистрации на русском; пустые необязательные
  поля не оставляют пустых блоков.
- **`AgentRegistrationForm`:**
  - `201` → переход на `/agents/{id}`;
  - `400` → ошибки у полей;
  - `409` → ошибка у поля «Имя»;
  - сетевая ошибка → общее сообщение;
  - кнопка неактивна во время отправки.
- **Layout:** «Агенты» — ссылка на `/agents` с `aria-current` на этой странице.

### E2E (Playwright, без моков)

- `/agents` показывает seed-агента; клик открывает его профиль с теми же данными.
- Пустая форма на `/agents/new` показывает ошибки валидации, агент не создаётся.
- Регистрация с уникальным именем → открыт профиль нового агента → он есть в `/agents`.
- Smoke-тест фазы 0 зелёный.

## 3. Ручной чек-лист (перед слиянием, на Windows)

- [ ] Оба приложения запущены по `README.md`; на `/` в шапке активна ссылка
      «Агенты».
- [ ] `/agents`: видны seed-агенты, отсортированные по имени; клик ведёт в профиль.
- [ ] `/agents/{id}`: все поля, дата на русском, ссылка «← Все агенты» работает.
- [ ] `/agents/999999` → страница 404, в консоли браузера нет необработанных ошибок.
- [ ] `/agents/new`:
  - пустая форма → ошибки у полей;
  - имя seed-агента в другом регистре → ошибка «имя занято»;
  - валидные данные → профиль нового агента, после обновления страницы данные
    на месте.
- [ ] Бэкенд остановлен → `/agents` показывает страницу ошибки, а не падает
      белым экраном; `/` по-прежнему показывает статус «недоступен».
