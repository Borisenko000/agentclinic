# Фаза 0. Скелет — требования

Ветка: `feature/phase-0-skeleton` · Дата: 2026-09-28
Ориентиры: [`mission.md`](../mission.md), [`tech-stack.md`](../tech-stack.md),
[`roadmap.md`](../roadmap.md) (этапы 0.1–0.6).

## Цель

Получить работающий «пустой» монорепозиторий AgentClinic, который можно показать
в браузере: фронтенд на Next.js открывает стартовую страницу с общим layout и
показывает статус бэкенда, полученный по REST API. Бэкенд на Spring Boot поднимает
SQLite через Flyway. Оба приложения покрыты тестами и проверяются в CI.

Сама фаза не даёт пользователю новых функций. Она готовит основу, на которую
опираются все следующие фазы (агенты, недуги, лечение, запись на приём).

## Область задачи

### Входит

| Этап | Результат |
|------|-----------|
| 0.1 | Maven-проект перенесён в `backend/`, подключён Spring Boot; `GET /api/health` отвечает «ok». |
| 0.2 | SQLite + Spring Data JPA + Flyway; пустая первая миграция `V1__init.sql` применяется при старте. |
| 0.3 | `frontend/` на Next.js (App Router) + TypeScript strict + Tailwind; стартовая страница «Добро пожаловать в AgentClinic». |
| 0.4 | Фронтенд вызывает `/api/health` и показывает статус бэкенда (включая состояние «недоступен»). |
| 0.5 | shadcn/ui подключён; общий layout: шапка, навигация, футер. |
| 0.6 | JUnit, Vitest + React Testing Library, Playwright-smoke; ESLint и Prettier; workflow GitHub Actions. |

Сюда же входит служебная работа: `.gitignore` для обоих приложений, `README.md`
с инструкцией по запуску и обновление `tech-stack.md` под выбранные версии.

### Не входит

- Предметные сущности (`Agent`, `Ailment` и т. д.): они начинаются с фазы 1.
- OpenAPI (springdoc) и генерация типов клиента. Подключаем, когда появится первый
  настоящий ресурс API (фаза 1). В фазе 0 нужен один эндпоинт, для него хватит
  типа, написанного вручную.
- Аутентификация, роли, визуальная айдентика, Docker, деплой.
- Spotless / форматирование Java и отдельный шаг `tsc --noEmit`: в обязательные
  проверки не входят (типы и так проверяются в `next build`).

## Принятые решения

| # | Решение | Почему |
|---|---------|--------|
| D1 | **Вся фаза 0 — одна ветка и один PR**, по коммиту на группу задач из `plan.md`. | Фаза маленькая и связная; каждый коммит по-прежнему соответствует этапу roadmap. |
| D2 | **Spring Boot 4.x, Java 21, Node 24 LTS**, последний стабильный Next.js. | Выбор пользователя: берём самые свежие версии. `tech-stack.md` обновляется в этой же ветке (там сейчас «Spring Boot 3»). |
| D3 | Maven: `groupId` `dev.polina`, `artifactId` `agentclinic-backend`; базовый пакет `dev.polina.agentclinic`. Шаблонный `Main.java` удаляется. | Имя пакета отражает продукт, а не учебный проект. |
| D4 | В dev-режиме фронтенд ходит в API **через прокси Next.js**: `rewrites` в `next.config` отправляет `/api/:path*` на `http://localhost:8080/api/:path*`. Адрес бэкенда задаётся переменной окружения `BACKEND_URL` со значением по умолчанию. | Один origin, CORS не нужен. Фронтенд обращается только к REST API, как требует `tech-stack.md`. |
| D5 | Пакетный менеджер фронтенда — **npm**, `package-lock.json` коммитится. | Входит в поставку Node, ничего ставить не нужно. |
| D6 | Запуск в разработке — **два терминала** (`./mvnw spring-boot:run` и `npm run dev`), команды описаны в `README.md`. Playwright сам поднимает оба приложения через `webServer`. | Минимум инструментов. |
| D7 | **Тесты пишутся сразу**, а не в конце: MockMvc-тест на health в 0.1, тест миграции Flyway в 0.2, Vitest-тест компонента статуса в 0.4. На этап 0.6 остаются Playwright, CI и сведение скриптов. | Каждый коммит проверяем; соответствует принципу «маленьких шагов». |
| D8 | `GET /api/health` — собственный контроллер (не Actuator), отвечает `200` с телом `{"status":"ok"}`. | Фиксированный и простой контракт для фронтенда; Actuator отвечает `UP` и тянет лишние эндпоинты. |
| D9 | Файл БД SQLite: `backend/data/agentclinic.db` (путь настраивается через `application.yml`), каталог `data/` в `.gitignore`. В тестах используется отдельная временная БД. | БД не попадает в репозиторий, тесты не трогают dev-данные. |
| D10 | Обязательные проверки стиля: **ESLint** и **Prettier** (`format:check`) во фронтенде. | Выбор пользователя. |
| D11 | CI — **GitHub Actions**: `./mvnw verify`, `npm run lint`, `npm run format:check`, `npm test`, Playwright-smoke. | Требование `tech-stack.md`: каждый PR проходит verify / lint / test. |

## Контекст и риски

- **Текущее состояние репозитория:** в корне лежит пустой Maven-проект (`pom.xml`,
  `src/main/java/dev/polina/Main.java`) и каталог `specs/`. Maven Wrapper нет, есть
  файлы IDE (`.idea/`).
- **Ветки:** локально есть только `master`, а в настройках основной указана `main`.
  Удалённого репозитория (remote) пока нет. Для CI из D11 нужно создать репозиторий
  на GitHub и договориться, какая ветка основная. Это нужно решить до открытия PR.
- **Spring Boot 4:** стартеры разбиты на модули (например, для Flyway нужен
  отдельный `spring-boot-starter-flyway`), Hibernate 7, Jackson 3. Совместимость
  `hibernate-community-dialects` (SQLiteDialect) и поддержку SQLite во Flyway надо
  проверить на первом же запуске (этап 0.2). Если что-то не заработает, фиксируем
  это здесь как новое решение.
- **Windows-разработка:** в скриптах и `webServer` Playwright учитываем `mvnw.cmd`
  и `mvnw`. CI работает на Linux.
- **Тон проекта:** шутки допустимы в текстах интерфейса, но не в коде и тестах
  (принцип 3 из `mission.md`).
